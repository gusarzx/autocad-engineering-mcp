# AutoCAD Engineering MCP

Локальный MCP-сервер `autocad-engineering` для управления **2D-чертежами** AutoCAD
через Codex. Геометрия создаётся редактируемыми объектами, оборудование — блоками
с атрибутами. Есть инструменты для схем ОВ и ВК, логической сети и спецификации.

[English](README_EN.md) · [Каталог 85 инструментов](docs/TOOLS.md) ·
[Примеры запросов](examples/codex_prompts.md) · [Проверка Windows](docs/WINDOWS_VERIFICATION.md)

**Статус: предварительная версия 0.1.0.** Реальный AutoCAD отсутствует на машине
разработки. Проверка COM, Windows installer и совместимости с AutoCAD 2027 ещё
предстоит. Локальные mock-тесты не являются проверкой AutoCAD. Это не официальный
продукт Autodesk или OpenAI. Проект не опубликован на GitHub или PyPI.

## Возможности и поддерживаемые версии

- 2D линии, полилинии, окружности, дуги, прямоугольники, многоугольники, текст,
  MText, сплайны, штриховки и линейные размеры.
- Перемещение, копирование, вращение, масштабирование, зеркалирование, offset,
  подтверждаемое удаление. Связанные инженерные элементы защищены от преобразований,
  которые нарушили бы метаданные сети.
- Слои, определения блоков, вставки, атрибуты и собственные 2D DWG-библиотеки.
- Пагинация чтения объектов, фильтры по слою, типу и MARK, чтение выделения и границ.
- Проверяемые пакеты создания, dry-run, группировка Undo и best-effort очистка COM.
- Схемы вентиляции, водоснабжения и канализации; плоская аксонометрия; спецификация.
- Безопасное сохранение DWG с ограничением путей, разрешением перезаписи и backup.

Целевая версия — полный AutoCAD 2027 для Windows. Autodesk документирует ActiveX
и версию 26.0; это подтверждение наличия API, а не успешного запуска данного сервера.
[Документация совместимости Autodesk](https://help.autodesk.com/cloudhelp/2027/DEU/AutoCAD-Customization/files/GUID-927E71C2-E515-438E-9D7A-246D97BEF93F.htm).
Другие версии можно разрешить явно при подключении, но их совместимость не заявлена.
AutoCAD LT, Mac, Web и неинтерактивные Windows services не являются проверенными целями.

## Требования

- Windows 10/11, установленный и запущенный AutoCAD 2027, интерактивный рабочий стол.
- Python 3.11+; рекомендуется 64-битный Python и одинаковые права с AutoCAD.
- Codex CLI либо поддерживающая локальный MCP версия Desktop/IDE Extension.
- Интернет для установки Python-зависимостей. Сам сервер работает локально по stdio.
- MCP Python SDK v2, Pydantic 2, pywin32 на Windows — устанавливаются автоматически.

MCP — протокол между Codex и небольшой локальной программой, которая предоставляет
инструменты. Он не заменяет AutoCAD и не запускает модель AI. API-ключ OpenAI для
самого сервера не нужен; вход в Codex выполняется отдельно. Этот stdio-сервер нужно
запускать на Windows-компьютере, где открыт AutoCAD. Mac не управляет им удалённо.
Сервер не содержит функции загрузки проекта или DWG в интернет. Передача данных
в AI-сервис определяется настройками клиента Codex.

## Установка AutoCAD Engineering MCP в Codex за 5 шагов

1. Передайте папку проекта другу локально и распакуйте, например, в
   `C:\CAD\autocad-engineering-mcp`. Установите Python 3.11+ с Python launcher
   и Codex, затем откройте PowerShell в папке проекта.
2. Установите сервер без автоматической регистрации:

   ```powershell
   Set-Location 'C:\CAD\autocad-engineering-mcp'
   powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -SkipCodexRegistration
   ```

   `Bypass` действует только в этом процессе PowerShell. Скрипт создаёт `.venv`,
   устанавливает пакет, проверяет компоненты и регистрацию AutoCAD. Он не меняет
   системный PATH, не запускает AutoCAD и не выполняет реальные COM-тесты.
3. Зарегистрируйте абсолютный путь к Python, чтобы запуск не зависел от PATH:

   ```powershell
   $McpPython = (Resolve-Path '.\.venv\Scripts\python.exe').Path
   $DwgRoot = Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'AutoCAD Engineering MCP'
   codex mcp add autocad-engineering --env 'ACAD_MCP_BACKEND=com' --env "ACAD_MCP_SAVE_ROOT=$DwgRoot" -- $McpPython -m autocad_engineering_mcp
   ```

4. Проверьте регистрацию и откройте AutoCAD вручную:

   ```powershell
   codex mcp list
   .\.venv\Scripts\python.exe .\scripts\check_environment.py
   ```

5. Начните новую сессию Codex в этой папке. Попросите:
   «Используй autocad-engineering. Подключись к запущенному AutoCAD без запуска
   нового экземпляра и покажи версию и активный документ. Пока ничего не меняй».
   Затем создайте новый тестовый документ и линию. Используйте checklist Windows
   перед работой с чертежами друга.

Официальная инструкция поддерживает CLI-регистрацию и конфигурацию MCP:
[Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).
`codex mcp list` проверяет запись конфигурации; успешное обнаружение и выполнение
инструментов проверяется в новой сессии Codex. Реальная регистрация в пользовательском
Codex при разработке не выполнялась.

## Установка через PowerShell

```powershell
# Интерактивно предложит регистрацию, если codex есть в PATH:
.\scripts\install.ps1

# Явная регистрация без вопроса установщика:
.\scripts\install.ps1 -RegisterCodex

# Задать разрешённую папку для DWG и пользовательских блоков:
.\scripts\install.ps1 -SkipCodexRegistration -SaveRoot 'C:\CAD\Drawings'

# Если Python launcher отсутствует:
.\scripts\install.ps1 -SkipCodexRegistration -PythonCommand 'python' -PythonArguments @()
```

Скрипт проверяет Python >=3.11 и сохраняет marker принадлежности `.venv`.
Чужое виртуальное окружение он не заменяет. Существующее ручное `.venv` обновляйте
вручную или используйте чистую папку. Отсутствие регистрации AutoCAD даёт предупреждение:
установить пакет можно и до установки AutoCAD, но COM до этого работать не будет.

## Ручная установка Windows

Из корня переданного проекта:

```powershell
py -3 -c "import sys; assert sys.version_info >= (3,11); print(sys.version)"
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install .
.\.venv\Scripts\python.exe .\scripts\check_environment.py
```

Не используйте `pip install autocad-engineering-mcp` без локальной точки: пакет
пока не опубликован. После изменения исходников переустановите `pip install .`
либо используйте `pip install -e ".[dev]"` для разработки.

## Настройка config.toml

Вместо CLI можно отредактировать `%USERPROFILE%\.codex\config.toml`. Пути в примере
предполагают установку в `C:\CAD\autocad-engineering-mcp`; замените их при необходимости.

```toml
[mcp_servers.autocad-engineering]
command = 'C:\CAD\autocad-engineering-mcp\.venv\Scripts\python.exe'
args = ["-m", "autocad_engineering_mcp"]
startup_timeout_sec = 20
tool_timeout_sec = 120

[mcp_servers.autocad-engineering.env]
ACAD_MCP_BACKEND = "com"
ACAD_MCP_SAVE_ROOT = 'C:\CAD\Drawings'
```

Используйте один способ регистрации, чтобы не создавать дубликаты. CLI и IDE
Extension используют конфигурацию MCP; для Desktop проверьте MCP-настройки вашей
установленной версии, включите сервер и перезапустите сессию при необходимости.
Не подключайте этот сервер как облачный HTTP-коннектор: реализован только stdio.

Запуск вручную для диагностики:

```powershell
$env:ACAD_MCP_BACKEND = 'com'
.\.venv\Scripts\python.exe -m autocad_engineering_mcp
# Или:
.\.venv\Scripts\autocad-engineering-mcp.exe
```

Сервер ждёт MCP-сообщений stdin, поэтому обычного приглашения команд не появится.
Завершение — Ctrl+C. Логи пишутся в stderr; stdout предназначен для протокола.

## Как пользоваться MCP после установки

Назовите систему, единицы, размеры, положение элементов и желаемую папку сохранения.
Попросите Codex сначала подключиться и показать активный документ. Для первых операций
создавайте новый документ. По умолчанию новые документы имеют INSUNITS=4, то есть мм.
Геометрические параметры принимают `units=mm/cm/m/in/ft`. Угол задаётся в радианах.
Все CAD-точки — `[x,y]` либо `[x,y,0]`; ненулевой Z отклоняется.

Сначала можно попросить пакетный dry-run. Он читает единицы, слои и определения блоков,
проверяет параметры и зависимости, возвращает план. Реальные изменения требуют
`dry_run=false`. В отдельных инструментах создания dry_run по умолчанию false;
у пакетного инструмента и сохранения — true.

Сохранение: «Сохрани копию как `ventilation.dwg` внутри разрешённой папки, существующий
файл не перезаписывай». Для намеренной перезаписи требуется `overwrite=true`; сначала
создаётся отдельная `.bak`. Для удаления требуется `confirm=true`, как и для изменения
более 20 объектов за вызов. Такие флаги передаются только после явного разрешения человека.
Нельзя выдавать dry-run за созданный чертёж или утверждать успех после `status=error`.

## Доступные MCP tools

Полный автоматически сформированный [каталог](docs/TOOLS.md) содержит 85 инструментов.
Группы: `autocad_*` — подключение и документы; `cad_draw_*` — 2D геометрия;
`cad_*` — слои, блоки, чтение, преобразования и пакеты; `hvac_*` — ОВ;
`plumbing_*` — ВК. `cad_generate_specification` собирает общую спецификацию,
`cad_get_engineering_network` возвращает логические узлы и связи.

Ответы содержат `status`, `object_ids`, `count`, `data`, `error`, `warnings`.
ID — строковые DWG handles, действуют только в соответствующем документе. Количество
показывает созданные/изменённые объекты модели; определения слоёв/блоков не считаются
геометрией. Ошибка schema validation также может вернуться стандартной ошибкой MCP.

## Работа с ОВ

Создайте `hvac_create_system` с `discipline=hvac` и `kind=supply/exhaust/heating`.
Прямоугольные воздуховоды требуют width/height, круглые — diameter. Размеры в мм,
расход — м³/ч, отметка — мм. Полилиния обозначает ось трассы; двойной контур и
автоматические фасонные части не строятся. Воздуховоды имеют логические вершины.
Для соединения ответвления включайте точку подключения в вершины магистрали.

Оборудование вставляется именованными блоками с MARK/NAME/TYPE/SIZE/SYSTEM/DESCRIPTION.
Встроенные блоки — оригинальные прямоугольные символы с крестом и маркировкой.
Они отличаются именами/типами и не являются нормативной библиотекой УГО.
Можно подставить собственные лицензированные символы через профиль.

```powershell
.\.venv\Scripts\python.exe .\examples\hvac_example.py --backend mock
# Позднее на Windows с открытым AutoCAD, в новом тестовом документе:
.\.venv\Scripts\python.exe .\examples\hvac_example.py --backend com --save hvac-test.dwg
```

Пример создаёт П1, магистраль 500×300, четыре ответвления 250×150, четыре решётки
и редактируемую текстовую спецификацию.

## Работа с ВК

`plumbing_create_system`: `discipline=plumbing`; kind: cold_water, hot_water,
hot_water_return, sanitary_sewer, rainwater. Проекция `plan` или `axonometric`.
Трубы хранят диаметр, материал, отметку, уклон (безразмерная доля 0..1), направление,
марку и длину. Уклон — параметр, не автоматическая коррекция трассы.

В аксонометрии входные **логические** XYZ-параметры в мм преобразуются в плоские
координаты: `X=(x-y)*sqrt(3)/2`, `Y=(x+y)/2+z`, `Z=0`. Это 2D-схема, не 3D-модель.
Длины спецификации берутся из логической трассы, а не искажённой проекции.

```powershell
.\.venv\Scripts\python.exe .\examples\plumbing_example.py --backend mock
.\.venv\Scripts\python.exe .\examples\plumbing_example.py --backend com --save plumbing-test.dwg
```

## Собственные блоки и оформление

Размещайте 2D DWG-библиотеки внутри `ACAD_MCP_SAVE_ROOT`, например
`C:\CAD\Drawings\blocks\fan.dwg`. `cad_insert_block` принимает такой путь или имя
существующего определения. Импорт/масштаб/атрибуты внешнего DWG требуют проверки
на Windows. Библиотека должна содержать только плоскую геометрию и необходимые теги.
Используйте только материалы, которые вправе использовать и распространять.

Профиль JSON задаётся явным `ACAD_MCP_PROFILE`. Пример:

```json
{
  "layers": {"HVAC_DUCT": 4, "HVAC_EQUIPMENT": 3, "TEXT": 7},
  "layer_names": {"HVAC_DUCT": "OV_DUCT", "TEXT": "OV_TEXT"},
  "linetype": "Continuous",
  "text_height": 150,
  "symbol_scale": 1,
  "symbols": {"hvac.fan": "blocks/fan.dwg"}
}
```

`layers` задаёт цвета семантических ролей, `layer_names` — реальные имена;
`symbols` выбирает определение или библиотеку для конкретного типа оборудования.
Тип линии должен быть уже загружен. Высоты текста профиля — мм, размеры `cad_create_block`
— единицы документа. Правило маркировки задаётся явно через `mark` в запросе.
Профили расширяются в `config.py`; соответствие СПДС/ГОСТ и проектным стандартам
проверяется инженером. Автоматическое соответствие ГОСТ/СП не заявлено.

## Ограничения и безопасность

- Только 2D, плоскость XY. Нет BIM, объёмных объектов, автоматической трассировки,
  аэродинамического/гидравлического расчёта и автоматической нормативной проверки.
- Читается ModelSpace; PaperSpace и оформление листов не реализованы.
- Спецификация читает наши XData и блоки с атрибутами; произвольные линии чужого DWG
  не распознаются как инженерная сеть. Отдельные дисциплинарные спецификации читают XData.
- Совпадение вершин сети с округлением до 0.001 мм образует узел; пересечения и
  оборудование посередине отрезка требуют явной вершины.
- Система без элементов живёт в сессии. После первого элемента система записана в
  XData; сохранение DWG сохраняет эти записи. После ручной правки геометрии вне MCP
  метаданные могут устареть. Нет автоматического мониторинга ручного редактирования.
- Пакеты поддерживают создание, а не произвольные команды/удаление/сохранение.
  Лимит 100 операций; невычислимые COM-ошибки dry-run не предсказывает. Штриховка
  ссылается только на уже существующие handles. Ошибка COM может оставить частичные
  изменения; best_effort очистка и Undo Mark не гарантируют транзакционность.
- По умолчанию 100 объектов на страницу, 10 000 на инженерный scan. Всегда используйте
  возвращённый `next_offset`. При превышении scan спецификация завершается ошибкой.
- План пакета ограничен 128 КБ. Если ответ превышает 128 КБ, детали опускаются с
  явным `response_truncated`; статус и handles сохраняются. Уменьшите страницу/запрос.
- Прямое изменение атрибутов связанных инженерных элементов заблокировано, чтобы
  не рассинхронизировать атрибуты и XData. Пересоздайте элемент инженерным инструментом.
- Mock хранит данные в памяти, не читает и не пишет DWG; offset в mock не симулируется.
- Запрещены произвольные AutoCAD-команды, AutoLISP, shell-команды и закрытие документов.
- SaveRoot ограничивает сохранение, открытие и внешние DWG-блоки; symlink-выход запрещён.
  Одновременная внешняя правка файлов/активного документа не поддерживается.

Основные настройки окружения: `ACAD_MCP_BACKEND`, `SAVE_ROOT`, `PROG_ID`,
`EXPECTED_VERSION`, `MAX_BATCH`, `MAX_CHANGE`, `PAGE_SIZE`, `SCAN_LIMIT`, `PROFILE`
(каждое имя с префиксом `ACAD_MCP_`). `.env.example` — памятка, не автозагружаемый файл.
Секреты и логины серверу не требуются и в проект не включены.

## Устранение ошибок

| Симптом | Действие |
| --- | --- |
| Python старше/младше нужного | `py -0p`, выберите Python >=3.11; системный Python Mac может быть 3.9 |
| `requires Windows` | На Mac/Linux используйте backend=mock; реальный COM запускается у друга |
| No running AutoCAD / ROT | Откройте AutoCAD, дождитесь готовности; используйте одинаковые права |
| COM HRESULT / busy | Закройте модальные окна. Проверьте частичные изменения перед повтором |
| Wrong version | Проверьте AutoCAD.Version, ProgID и registry report; не обходите без понимания |
| Unitless drawing | Создайте документ с units=4 либо задайте INSUNITS в AutoCAD вручную |
| Layer/block not found | Сначала создайте определение; пакетный порядок имеет значение |
| Missing attribute | Добавьте стандартные теги в свой блок; вставка без нужных тегов отменяется |
| Path rejected | Используйте файл внутри явно заданного SAVE_ROOT с расширением .dwg |
| Existing DWG | Выберите новое имя либо явно разрешите overwrite; будет создан backup |
| MCP tools не видны | Проверьте абсолютный Python, установку пакета, `codex mcp list` и новую сессию |
| Scan limit reached | Увеличьте SCAN_LIMIT осознанно или разделите большой проект |

## FAQ

**Можно разрабатывать без AutoCAD?** Да, mock и unit-тесты доступны на Mac/Linux.
**Нужен платный OpenAI API-ключ?** Серверу — нет; используйте доступный вам клиент Codex.
**Будет настоящий DWG?** COM вызывает AutoCAD SaveAs. Эта ветка реализована, но пока
не проверена на Windows. Mock DWG не создаёт.
**Есть ГОСТ-библиотека?** Нет. Встроенные символы иллюстративные; подключайте свою библиотеку.
**Запустит ли AutoCAD сам?** Только после явного `allow_launch=true`; обычно открыть вручную.
**Как удалить?** Installer-owned `.venv`: сначала `.\scripts\uninstall.ps1 -WhatIf`,
затем `.\scripts\uninstall.ps1`; `-RemoveCodexRegistration` удаляет также запись Codex.
Ручную установку удаляйте через `.\.venv\Scripts\python.exe -m pip uninstall autocad-engineering-mcp`.
AutoCAD, исходники и DWG uninstaller не удаляет.

## Архитектура

```text
src/autocad_engineering_mcp/
  server.py, config.py       MCP v2, stdio, конфигурация
  core/                     модели, единицы, безопасность, сервис
  adapters/                 протокол, mock, COM STA, ActiveX geometry
  tools/                    CAD и инженерные инструменты, schema registration
  engineering/              ОВ/ВК, плоская проекция, сеть, спецификация
  resources/                пример профиля
examples/ scripts/ tests/ docs/ .github/workflows/
```

COM-вызовы сериализуются одним worker STA с message pump. COM-ссылки не возвращаются
из потока: только числа, строки, списки и словари. Блокировка сервиса сохраняет
целостный порядок инженерного сценария; активный документ нельзя переключать вручную
во время операции. Через `Adapter` можно добавить будущий .NET backend.

## Разработка и тестирование

Python 3.11+ на любой ОС, из корня проекта:

```console
python3.11 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
.venv/bin/ruff format --check .
.venv/bin/ruff check .
.venv/bin/python -m pytest -m "not autocad"
.venv/bin/python -m build
```

На Windows замените `.venv/bin/` на `.venv\Scripts\`. Для проверки запуска на Mac:

```console
ACAD_MCP_BACKEND=mock .venv/bin/python -m autocad_engineering_mcp
```

Unit-тесты проверяют модели, координаты, единицы, геометрию mock, инженерную сеть,
спецификации, ошибки batch, dry-run/rollback, пути, schema и stdio. Windows integration
тесты требуют отдельного явного флага и не выполняются в обычном запуске.
Полный порядок — [Windows verification](docs/WINDOWS_VERIFICATION.md).
GitHub Actions подготовлен для Ruff, unit-тестов и сборки на трёх ОС; он ещё не запускался
на GitHub. Публикация репозитория выполняется владельцем отдельно.
